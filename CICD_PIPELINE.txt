GLIDEGATE CI/CD PIPELINE - KT DOCUMENT
================================================================================

OVERVIEW
--------
Every push to the COPS_Agentic_AI_Deploy branch automatically triggers a
4-stage GitLab CI/CD pipeline that validates, builds, and deploys the
application to an AWS EC2 instance.

================================================================================
STAGES
================================================================================

STAGE 1 - PREPARE
------------------
Purpose : Force-sync the EC2 deployment directory with the latest remote branch.

Commands:
    cd /home/ubuntu/office_project/glidegate
    git fetch origin
    git reset --hard origin/COPS_Agentic_AI_Deploy

Why reset --hard instead of git pull:
    git pull can fail silently if EC2 has local changes or diverged history.
    reset --hard forces exact match with remote - no stale or missing files.

Failure impact: Pipeline stops. No code change on EC2.

--------------------------------------------------------------------------------

STAGE 2 - VALIDATE (validate-frontend)
---------------------------------------
Purpose : Verify the frontend compiles before spending time on Docker builds.

Commands:
    sudo rm -rf frontend/node_modules   (clear root-owned modules from Docker)
    cd frontend
    npm install --legacy-peer-deps
    npm run build                       (tsc -b + vite build, strict TS check)

Environment : Node.js 18 installed on EC2 (matches node:18-alpine in Dockerfile)

Why npm run build and not npm run dev:
    npm run build runs tsc -b (strict TypeScript) + vite build.
    Catches type errors, missing imports, unused variables.
    npm run dev is lenient and only shows errors in the browser.

Failure impact: Pipeline stops. Docker build never starts. Running containers
                untouched.

--------------------------------------------------------------------------------

STAGE 3 - BUILD
---------------
Purpose : Build production Docker images, tag with git commit SHA.

Commands:
    mkdir -p db/data
    sudo chown -R 999:999 db/data
    DOCKER_BUILDKIT=0 docker-compose build
    docker tag glidegate_backend:latest  glidegate_backend:<SHA>
    docker tag glidegate_frontend:latest glidegate_frontend:<SHA>
    (prune images older than last 3 versions)

Docker build checks per service:
    Service   | Base Image       | Build Check
    ----------|------------------|------------------------------------------
    Backend   | python:3.12-slim | from app.main import app (import check)
    Frontend  | node:18-alpine   | npm run build (TypeScript compile check)

Image versioning:
    Each build creates glidegate_backend:<git-SHA> and
    glidegate_frontend:<git-SHA>. Last 3 versions kept on EC2 for rollback.
    latest tag always points to current build.

Why DOCKER_BUILDKIT=0:
    BuildKit is enabled globally on EC2 but buildx is not installed.
    Legacy builder is used instead.

Failure impact: Pipeline stops. Running containers untouched. Previous images
                preserved for rollback.

--------------------------------------------------------------------------------

STAGE 4 - DEPLOY
----------------
Purpose : Replace running containers with newly built images.

Commands:
    docker-compose down
    bash docker-startup.sh
    docker-compose ps

docker-startup.sh sequence:
    1. docker-compose up -d  (start all 3 services)
    2. Wait for PostgreSQL to be ready (pg_isready)
    3. Wait for backend health check (/api/health returns 200)
    4. Confirm frontend container is running
    5. Print service URLs and container status

Services started:
    Container              | Port | Health Check
    -----------------------|------|---------------------------
    glide_gate_db          | 5432 | pg_isready
    glide_gate_backend     | 8000 | GET /api/health
    glide_gate_frontend    | 5173 | node http check

Failure impact: If deploy fails, docker-compose down has already run.
                Manual intervention needed to restart containers.

    http://18.60.103.228:8000/api/health  - Backend health + DB connectivity
    http://18.60.103.228:5173             - Frontend Vite server
    http://18.60.103.228:8000/api/docs    - Swagger API documentation

Backend health response:

        "status": "ok",
        "timestamp": "2026-06-02T08:00:00Z",
        "version": "0.1.0",
        "env": "development",
        "database": "connected",
        "demo_mode": false
    }

Docker-level (checked by Docker every 30s):
    Container          | Command                      | Interval
    -------------------|------------------------------|----------
    glide_gate_db      | pg_isready -U postgres       | 10s
    glide_gate_backend | python urllib check :8000    | 30s
    glide_gate_frontend| node http check :5173        | 30s

Check on EC2:
    docker compose ps
    (shows healthy / unhealthy / health: starting for each container)


================================================================================
ROLLBACK
================================================================================

SSH into EC2:
    ssh -i your-key.pem ubuntu@18.60.103.228
    cd /home/ubuntu/office_project/glidegate

List available versions:
    ./rollback.sh

Roll back to specific commit:
    ./rollback.sh <git-commit-sha>

rollback.sh re-tags the selected version as latest and restarts containers.
